# wompi

A small Laravel storefront that takes payments through the [Wompi](https://docs.wompi.co/) Web Checkout (Colombia). Built on the `laravel/react-starter-kit` scaffold: Laravel 13 / PHP 8.3, Inertia v3 + React 19 + TypeScript, Tailwind v4, Vite, SQLite.

## What it does

- Browse a seeded product catalog, add items to a per-user cart, adjust quantities.
- Manage shipping addresses and stored payment cards under **Settings** (with Luhn and card-brand validation).
- Check out: the order and its line items are snapshotted server side, the customer is handed off to Wompi Web Checkout, and the order is settled either on the redirect back or by webhook — whichever arrives first.
- Authentication (login, register, password reset, email verification, 2FA, passkeys) is handled by Laravel Fortify.

## Requirements

- PHP 8.3+
- Node 20+
- Composer

## Getting started

```bash
composer setup                 # install deps, .env, key:generate, migrate, npm build
php artisan db:seed            # test@example.com + product catalog
composer dev                   # serve + queue:listen + vite, concurrently
```

Then browse the app — see the note on hostnames below before trying a payment.

## Wompi configuration

Credentials come from the environment; only the public key ever reaches the browser. Keys must match their environment: `stagtest_` keys pair with the UAT hosts, `test_` keys with `https://sandbox.wompi.co`, `prod_` keys with production.

| Variable | Purpose |
| --- | --- |
| `WOMPI_BASE_URL` | API host for transaction lookups (default: UAT sandbox) |
| `WOMPI_CHECKOUT_URL` | Web Checkout endpoint the pay button redirects to |
| `WOMPI_PUBLIC_KEY` | Public key — used in the checkout URL and to read transactions |
| `WOMPI_PRIVATE_KEY` | Private key (server side only) |
| `WOMPI_EVENTS_SECRET` | Verifies the checksum on incoming webhook events |
| `WOMPI_INTEGRITY_SECRET` | Signs the checkout amount/reference so it cannot be tampered with |
| `WOMPI_CURRENCY` | Settlement currency (Wompi Colombia settles in `COP`) |
| `WOMPI_REDIRECT_URL` | Optional override for where Wompi returns the customer |

See [config/wompi.php](config/wompi.php) for the full annotated config.

### The localhost trap

Wompi fronts Web Checkout with a WAF that **rejects a `redirect-url` naming `localhost`, `127.0.0.1`, or a private LAN address** and answers the whole checkout request with an opaque CloudFront 403. Browsing at `http://localhost:8000` therefore cannot complete a payment.

Either browse the app at a non-loopback hostname (`http://wompi.localhost:8000`, with `APP_URL` set to match) or point `WOMPI_REDIRECT_URL` at a tunnel. [`WompiGateway`](app/Services/WompiGateway.php) checks this up front and throws a readable exception instead of letting the 403 happen.

### Webhooks

Wompi posts events to `POST /wompi/events` ([routes/web.php](routes/web.php)). The route is public, stateless, and CSRF-exempt (see [bootstrap/app.php](bootstrap/app.php)); every event's checksum is verified against `WOMPI_EVENTS_SECRET` before it can move an order. Verified events always answer `200` — even duplicates and unknown references — so Wompi does not retry them.

## Payment flow

1. `GET /checkout` renders a read-only cart summary.
2. `POST /checkout` creates the `Order` plus snapshotted `OrderItem` rows in one transaction, derives the amount and integrity signature server side, and returns `Inertia::location(...)` so the browser performs a full visit to Wompi.
3. The customer pays on Wompi's hosted page.
4. `GET /checkout/result` looks the transaction up, verifies it matches the order (scoped to the authenticated user), settles it, and empties the cart when approved.
5. `POST /wompi/events` settles the order the same way if the customer never returns.

Order statuses map from Wompi's `PENDING / APPROVED / DECLINED / VOIDED / ERROR`; anything unrecognised becomes `Error` rather than being silently approved. See [app/Enums/OrderStatus.php](app/Enums/OrderStatus.php).

## Development

```bash
composer ci:check         # what CI runs: lint:check → format:check → types:check → test
composer test             # config:clear → pint --test → phpstan (level 7) → artisan test
php artisan test --compact --filter=CheckoutTest
npm run types:check
vendor/bin/pint --dirty   # format changed PHP
php artisan wayfinder:generate                      # regenerate TS route/action helpers
```

`resources/js/actions/` and `resources/js/routes/` are generated by the Wayfinder Vite plugin — never hand-edit them; import typed helpers from `@/actions/…` and `@/routes/…` instead of hardcoding URLs.
